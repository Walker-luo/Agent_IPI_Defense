框架介绍：BaseIntent

BaseIntent 将工具授权、目标进度和动作审计分开：L2 确定任务可用的工具，宿主和语义判断跟踪当前目标，L3 审计需要审查的具体调用。L1 为每次规划重建工具返回视图，Monitor 则介导整批执行。下方按职责介绍各部分；实际运行从可信有效任务和 L2 授权开始。

第一层 · 工具返回隔离
外部结果与错误正文原消息保留给日志与审计
有限字段投影 / 来源封装月支出省略交易备注；不适用则保留原文
主模型规划视图来源标记是提示，不认证事实
L1 投影仅支持原生银行月支出任务，不认证事实；必要分析与引用保留原文。L2 授权只来自可信任务与宿主策略
第二层 · 可信任务工具授权
有效用户任务明确委托的文件先准备读取
两次调用：目标，再选工具宿主归并准备前缀并分配固定 ID
候选权限前置检查非法混合批次整体拒绝
规划和 L3 使用同一完整有效任务；工具授权是全局集合，不是按意图动态授予。非法或未授权候选使整批在 L3 前被拒绝
第三层 · 当前动作语义审计
当前候选动作工具、参数与有限动作历史
任务对齐审计外发同时核对正文与目的地
严格四字段审计结论decision / violations / confidence / reason_code
L3 依据当前目标、完整原始约束、原生 schema、效果与有界证据审计；注入文字本身不等于违规
执行基础设施 · Monitor / 一次性票据
原生整批执行仲裁保持顺序 · 混合批次仅审计非豁免子集
一次性执行许可绑定原调用 · 使用后失效
真实工具执行结果返回主模型
工具反馈经 L1 返回主模型；新候选重新经过 L2、L3 和票据校验。宿主记录实际事实、效果和最终回复；需要语义判断时，模型只返回满足状态和证据引用，宿主核验成功账本或实际消息后逐项推进。
L1 · 规划视图
保留原始证据

每次从原始历史重建视图，普通返回和错误带来源标记。仅有界银行月支出任务可投影交易字段；不支持或无收益时回退封装。原始返回仍供审计和原生轨迹使用，来源标记不保证内容真实。

L2 · 授权与关联
全局权限在任务内冻结

第一次调用分解目标及类型，宿主无损归并准备前缀并分配 ID；第二次选择全局工具并关联准备与完成足迹（prepare_tools / completion_groups）。进度关联不能授予或禁止工具。默认前置检查对注册、权限和原生 schema 整批校验。

进度 · 执行证据
逐项推进目标

宿主管理状态并核对实际成功调用或消息；错误、阻挡和助手声称完成都不是执行证据。复杂目标仍需语义判断；未知条件不等于 false。自动完成仅限已审核的有界单次直接邀请场景。

L3 · 动作审计
按目标和约束判断

审计使用当前目标、完整任务约束、原生工具定义及有界证据；外发同时检查正文和目的地。判决严格为 allow、deny 或 abstain 及对应字段；无解析修补或默认放行。

L3 · 固定读取免审
所有路由模式生效

已注册、已授权且 schema 合法的 public/internal 读取免审；personal/secret 读取与效果调用仍审计。免审不筛选 URL、sink 或对象隐私；internal 工具可能读取私有频道。

Monitor · 执行
整批回执与一次性票据

混合批次只审计非免审部分，仍按原顺序介导整批。执行前复核权限、目录及意图状态，票据绑定调用与上下文并防止重放。

任务来源
仅展开明确委托

受支持的明确委托来源先经监控读取，再与原用户约束组成有效任务；普通返回不能扩权或递归委托。读取失败、歧义和超限时失败关闭，用户确认后受污染的任务文件不在支持范围。

配置与边界
路由 off 仍保留 L3

网页/API 默认 off，CLI 默认 shadow；三种路由共享固定免审范围。工具级授权不保证对象或参数权限，最终纯文本没有独立动作审计；语义满足判断也不等于事实认证。
